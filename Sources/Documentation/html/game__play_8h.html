Description détaillée

Fonctions appelées par l'interface (GUI) pour gérer les entrées utilisateur. C'est ici que la logique du jeu doit être implémentée.

Ce fichier déclare les fonctions que l'interface appelle pour gérer les interactions utilisateur pendant la partie. Vous devez implémenter ces fonctions pour traiter les clics de souris, les demandes d'indice, les détonations, les changements de gravité et les utilisations de la file de stockage. Il vous revient également de gérer les animations :

  • Vous pouvez démarrer des animations avec la fonction "game_init_animation" qui est déjà écrite.
  • Une fois une animation démarrée, l'interface bloque les entrées utilisateur jusqu'à la fin de l'animation. À ce moment-là, elle appelle la fonction "game_end_animation" que vous devez implémenter pour gérer les étapes suivantes.
Attention
Vous pouvez écrire des fonctions utilitaires supplémentaires si nécessaire, mais vous ne devez PAS modifier les prototypes de fonctions fournis dans ce fichier.

◆ game_init_animation()

void game_init_animation ( anim_type type)

Démarre une animation du type spécifié.

Appelez cette fonction lorsque vous voulez démarrer une animation. Elle bloque les entrées du jeu jusqu'à ce que l'animation soit terminée. À ce moment-là, la fonction game_end_animation (que vous devez écrire) est appelée. Cela vous permet de gérer la fin de l'animation et la transition vers l'état de jeu suivant.

Remarques
Puisque l'implémentation du plateau vous revient, l'interface ne peut pas récupérer directement dans la structure de jeu les informations nécessaires pour afficher l'animation. Elle le fait en appelant les fonctions déclarées à la fin de ce fichier. Vous devez donc écrire ces fonctions pour que les animations s'affichent correctement.
Attention
Cette fonction est DÉJÀ ÉCRITE. Vous ne devez pas la modifier.
Paramètres
typeType d'animation à démarrer.

◆ game_handle_mouse_click()

void game_handle_mouse_click ( game * g,
int i,
int j )

Appelée par l'interface lorsqu'un clic souris est effectué sur une case du plateau.

Cette fonction est appelée lorsque l'utilisateur clique sur une case du plateau. Si les coordonnées sont valides, la fonction doit effectuer les étapes suivantes :

  • Si aucune case n'est actuellement sélectionnée, sélectionner la case cliquée sans démarrer d'animation.
  • Si une case est déjà sélectionnée mais que c'est la même que la case cliquée, la désélectionner sans démarrer d'animation.
  • Si une case différente est déjà sélectionnée et que la case cliquée n'est PAS adjacente, désélectionner la case précédemment sélectionnée et sélectionner la case cliquée sans démarrer d'animation.
  • Si une case différente est déjà sélectionnée et que la case cliquée EST adjacente, tenter d'échanger la case sélectionnée avec la case cliquée. Si l'échange est valide (c.-à-d. crée au moins une zone destructible), démarrer une animation GOODSWAP. S'il est invalide (c.-à-d. ne crée aucune zone destructible), démarrer une animation BADSWAP.
Attention
Lorsqu'une animation est démarrée, l'interface bloque les entrées jusqu'à la fin de l'animation. À ce moment-là, elle appelle la fonction "game_end_animation" que vous devez implémenter pour gérer la suite. Par exemple, après une animation GOODSWAP, vous devrez démarrer une animation KILL car des zones destructibles sont à supprimer. À l'inverse, après une animation BADSWAP, vous devrez annuler l'échange avec une animation ROLLBACK.
Paramètres
gPointeur vers la structure du jeu.
iCoordonnée horizontale de la case dans le plateau (de gauche à droite).
jCoordonnée verticale de la case dans le plateau (de haut en bas).

◆ game_handle_refill()

void game_handle_refill ( game * g,
int k )

Appelée par l'interface lorsqu'un le joueur veut récupérer un objet dans la file de stockage.

Cette fonction remplit le plateau depuis la file de stockage (si cette file n'est pas vide). Elle fait tomber l'objet récupéré depuis le côté opposé à la gravité à partir de l'indice spécifié en entrée.

Cette fonction ne peut être utilisée qu'en mode puzzle lorsque la file de stockage est activée. Après avoir placé la gemme sur le plateau, la fonction doit démarrer une animation FALL pour faire tomber l'objet jusqu'à sa position.

Remarques
Si la demande ne peut pas être satisfaite (par exemple parce que la file de stockage est vide ou qu'il n'y a pas de place disponible sur le plateau pour placer la gemme), la fonction doit retourner sans rien faire (en particulier, aucune animation n'est démarrée).
Paramètres
kIndice de la file de stockage à utiliser pour le remplissage.

◆ game_end_animation()

void game_end_animation ( game * g,
anim_type type )

Appelée par l'interface lorsqu'une animation se termine.

Cette fonction est appelée lorsqu'une animation démarrée (par vous) avec game_init_animation se termine. Elle fournit le type d'animation qui vient de se terminer afin que vous puissiez gérer la suite du jeu. La suite dépend du type d'animation et de l'état du jeu. Deux exemples :

Quand une animation FALL se termine, vous devez vérifier si des gemmes peuvent être éliminées,

  • si oui, mettez à jour l'état du jeu en conséquence et démarrez une animation KILL pour supprimer ces gemmes ;
  • sinon, revenez à l'animation IDLE (qui permet de nouvelles entrées utilisateur).

Quand une animation KILL se termine, vous devez vérifier si des gemmes peuvent tomber selon la gravité,

  • si oui, mettez à jour l'état du jeu en conséquence et démarrez une animation FALL pour les faire tomber ;
  • sinon, revenez à l'animation IDLE (qui permet de nouvelles entrées utilisateur).
Remarques
C'est également ici que vous devez mettre fin à une partie :
  • en mode classique, si un niveau a été terminé, appelez la fonction game_classic_score ;
  • en mode classique, si le joueur n'a plus de coups (le joueur a perdu), appelez game_classic_end ;
  • en mode puzzle, si le plateau est vide (le joueur a gagné), appelez game_puzzle_end.
Paramètres
gPointeur vers la structure du jeu.
typeType de l'animation qui vient de se terminer.

◆ game_get_cell_move()

direction game_get_cell_move ( game * g,
int i,
int j,
int * distance )

Appelée par l'interface uniquement lors des animations MOVE. Elle l'utilise pour récupérer les informations de déplacement des cases à afficher.

Lors du premier appel (au début de l'animation), chaque élément doit déjà être à sa position finale (c.-à-d. après l'application du mouvement sur le plateau). Pour une case donnée, l'interface appelle cette fonction afin de savoir si le contenu de la case doit être déplacé depuis une autre position vers sa position actuelle et, le cas échéant, la direction et la distance du déplacement.

Par exemple, si la fonction renvoie la direction LEFT et une distance 3 pour une case donnée, cela signifie que durant l'animation MOVE, le contenu démarrera 3 cases à DROITE de sa position actuelle et se déplacera vers la GAUCHE pour atteindre sa position finale.

Remarques
Les quatre animations de déplacement sont gérées de manière identique par l'interface.
Renvoie
La direction du déplacement. La distance parcourue est affectée au pointeur fourni.
Paramètres
gPointeur vers la structure du jeu.
iCoordonnée horizontale de la case dans le plateau (de gauche à droite).
jCoordonnée verticale de la case dans le plateau (de haut en bas).
distancePointeur pour stocker la distance (peut être NULL si non nécessaire).

◆ game_get_cell_kill()

gem_kill game_get_cell_kill ( game * g,
int i,
int j )

Appelée par l'interface uniquement lors d'une animation KILL. Elle l'utilise pour récupérer les informations sur les cases à éliminer et l'animation à utiliser.

Lors de l'appel, les éléments à éliminer doivent encore être sur le plateau (au démarrage d'une animation KILL, les éléments ne sont pas encore retirés ; ils sont seulement marqués, car l'interface doit connaître les types de gemmes à afficher). Pour chaque case, l'interface appelle cette fonction pour savoir si la case est marquée pour élimination et, le cas échéant, quelle animation utiliser.

Renvoie
KILL_NOKILL si la case n'est pas marquée pour élimination ; sinon, l'animation d'élimination à afficher.
Paramètres
gPointeur vers la structure du jeu.
iCoordonnée horizontale de la case dans le plateau (de gauche à droite).
jCoordonnée verticale de la case dans le plateau (de haut en bas).
