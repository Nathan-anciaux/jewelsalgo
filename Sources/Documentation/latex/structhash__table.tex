\doxysubsection{Description détaillée}
Solveur pour le mode puzzle. 

Ce module fournit des fonctionnalités pour résoudre les puzzles à l\textquotesingle{}aide de divers algorithmes de parcours de graphe (DFS, BFS et A\texorpdfstring{$\ast$}{*}). Une implémentation de table de hachage est également fournie pour stocker efficacement les configurations de plateau visitées par ces algorithmes. Elle est déjà programmée et vous NE DEVEZ PAS LA MODIFIER. Les seules fonctions à implémenter sont \doxylink{game__solver_8h_ae40d02a25ab6ff6768ba20afeaeb359c}{solve\+\_\+puzzle()} et \doxylink{game__solver_8h_a1c56651acd6cef04890086deb4ee0011}{game\+\_\+implement\+\_\+solver\+\_\+move()} à la fin de ce fichier (vous pouvez bien sûr ajouter vos propres fonctions utilitaires).

\begin{DoxyRemark}{Remarques}
La table de hachage ne peut stocker que des éléments encodés comme des tableaux d\textquotesingle{}entiers. Cela signifie que pour stocker des configurations de plateau, vous devez d\textquotesingle{}abord les encoder sous forme de tableaux d\textquotesingle{}entiers. De plus, la table de hachage ne stocke pas les éléments eux-\/mêmes, mais des indices vers un tableau de stockage externe que vous devez gérer vous-\/même.
\end{DoxyRemark}
Structure de table de hachage.

Utilisée pour stocker les configurations de plateau visitées par le solveur. La table de hachage ne stocke pas les configurations elles-\/mêmes, mais des indices vers un tableau de stockage externe passé aux fonctions de la table (nécessaire car ce tableau de stockage peut être réalloué et déplacé en mémoire).

\begin{DoxyRemark}{Remarques}
Chaque élément inséré doit être encodé dans le tableau externe comme une séquence d\textquotesingle{}entiers (de longueur fixe, définie à la création de la table). En particulier, les configurations de plateau doivent être encodées sous forme de tableaux d\textquotesingle{}entiers. 
\end{DoxyRemark}
